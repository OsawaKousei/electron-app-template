SQLiteメモアプリ 仕様書 (webpack版)
1. 概要
本ドキュメントは、Electronの汎用テンプレートとして開発する「SQLiteを使用したメモアプリ」のディレクトリ構成と、各ファイルの役割分担を定義するものである。本仕様は、責務の分離、セキュリティ、保守性を重視したベストプラクティスに従う。 

2. アーキテクチャ概要
アプリケーションは、Electronの メインプロセス と レンダラープロセス に明確に分離される。 


メインプロセス: Node.js環境で動作し、ウィンドウ管理、OSネイティブ機能、データベースアクセスなど、アプリケーションのバックエンド処理全体を担当する。 


レンダラープロセス: Chromium環境で動作し、Reactを用いてUIの描画とユーザーインタラクションを担当する。 


プロセス間通信 (IPC): 両プロセスは直接通信せず、セキュリティを確保するために プリロードスクリプト を介して安全に通信する。

4. 各ファイルの役割詳細
4.1. src/main/database.ts

役割: データベース操作層 

責務:


better-sqlite3ライブラリを使用し、データベースファイル(memo.db)への接続を管理する。 

アプリケーション初回起動時に、メモを保存するためのテーブル(memos)を作成する。 

メモに関する全てのCRUD（作成, 読み取り, 更新, 削除）操作を行う関数を実装し、エクスポートする。 

このファイルは、UIやElectronのAPIを一切意識しない、純粋なデータ操作ロジックに特化する。 

4.2. src/main/index.ts

役割: メインプロセス エントリーポイント 

責務:

アプリケーションのライフサイクル（起動、終了、ウィンドウが閉じた時など）を管理する。 


BrowserWindowを生成し、UI（index.html）をロードする。 


ipcMainを使用し、レンダラープロセスからの通信要求を受け付ける APIサーバー としての役割を担う。 

受信したリクエストに応じてdatabase.tsの関数を呼び出し、その結果をレンダラープロセスに返す。 

4.3. src/preload/index.ts

役割: プロセス間通信のブリッジ (セキュリティの要) 

責務:

レンダラープロセスと同じウィンドウコンテキストで実行されるが、Node.jsのAPIにアクセスできる特権を持つ。 


contextBridge.exposeInMainWorldを使い、レンダラープロセスのwindowオブジェクトに安全なAPI（例: window.dbAPI）を公開する。 

公開するAPIは、ipcRenderer.invokeを介してメインプロセスの特定のIPCチャネルを呼び出す関数のみとする。 

これにより、レンダラープロセスが任意のNode.js機能を実行することを防ぎ、セキュリティを確保する。 

4.4. src/renderer/components/

役割: React UIコンポーネント 

責務:

UIを構成する再利用可能な部品（メモ一覧、個々のメモ、入力フォームなど）を格納する。 

状態やロジックは持たず、親コンポーネントから渡されたpropsに基づいて描画とイベントハンドリングを行う。 

4.5. src/renderer/App.tsx

役割: ルートコンポーネント 

責務:

アプリケーションUIの全体的なレイアウトを定義する。 


useEffectを用いて、プリロードスクリプトが公開したwindow.dbAPI経由でメモデータを取得する。 

取得したデータやUIの状態をReactのuseStateで管理する。 

各UIコンポーネントに状態と、状態を更新するためのコールバック関数をpropsとして渡す。 

4.6. src/renderer/main.tsx

役割: レンダラープロセス エントリーポイント 

責務:

Reactアプリケーションの起動点。 


ReactDOM.createRootを使い、Appコンポーネントをindex.html内のDOM要素にマウントする。 

4.7. src/shared/types.ts

役割: 共有型定義 

責務:

メインプロセスとレンダラープロセスの両方で使用されるTypeScriptの型を定義する。 

例: メモオブジェクトの型（{ id: number; content: string; }）、プリロードスクリプトが公開するAPIのインターフェース。 

これにより、プロセス間のデータ通信における型安全性を保証する。 

4.8. index.html

役割: HTMLルート 

責務:

レンダラープロセスの描画基盤となる唯一のHTMLファイル。 

Reactアプリケーションがマウントされるためのルート要素（例: <div id="root"></div>）を持つ。 

4.9. package.json

役割: プロジェクト定義 

責務:

プロジェクト名、バージョン、依存パッケージ（dependencies, devDependencies）を管理する。  これにはwebpack, webpack-cli, ts-loader, html-webpack-pluginなどのビルド関連のパッケージが含まれる。


npm run devやnpm run buildなどの開発用スクリプトを定義する。 

ビルド後のアプリケーションのエントリーポイント（"main": "dist/main.js"など）を指定する。 

4.10. webpack.config.ts
役割: ビルド設定

責務:

webpackビルドツールの設定を定義する。

メイン、プリロード、レンダラーの各プロセス用の設定を個別に定義する（エントリーポイント、出力先、ターゲットなど）。

ts-loaderなどを用いてTypeScriptファイルをJavaScriptにトランスパイルする設定を行う。

html-webpack-pluginを使い、ビルドされたレンダラープロセスのJavaScriptを読み込むindex.htmlを自動生成する。

開発モードと本番モードで設定を切り替え、それぞれの環境に最適化されたビルドを行う。
